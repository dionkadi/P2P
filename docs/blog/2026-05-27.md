# Taming a C++ P2P Codebase: Integration Test Flakiness, Coroutine Bugs, and Step-by-Step Refactoring

**Date:** 2026-05-27

## Session Overview

Six major categories of work:

1. **Refactoring** — nine steps applying SOLID/DRY/KISS/SRP to a ~6000-line C++23 BitTorrent client
2. **`bad_weak_ptr` during construction** — how to use `shared_from_this()` in constructor-based init
3. **Circular `shared_ptr` death spiral** — coroutine closures that prevent object destruction
4. **`stack-use-after-return`** — lambda captures pointing at stack-local data in async init chains
5. **Integration test flakiness** — the `io_context::restart()` trap and fixed-port races
6. **Tracker HTTP listener shutdown** — missing `stop_http_listener()` for clean teardown

Below, each problem is described with its root cause, the fix, and the reasoning.

## 1. Codebase Refactoring (Steps 2–9)

We audited the codebase against [PRINCIPLES.md](../../PRINCIPLES.md) (SOLID, KISS, YAGNI, DRY, SoC) and fixed one violation per step, testing after each.

### Step 2: DRY — `url_decode`
**Problem:** Three independent `url_decode` implementations in `Tracker.hpp`, `MagnetUri.hpp`, and `Utils.hpp`.
**Fix:** Kept the one in `Utils.hpp` (shared hub), removed the other two.
**Why it worked:** `Utils.hpp` is already included everywhere; duplicate implementations only drift apart.

### Step 3: DRY — Tracker client construction
**Problem:** `TorrentSession` had an inlined loop constructing `TrackerClient` objects duplicated at multiple call sites.
**Fix:** Extracted a delegating constructor.
**Result:** ~20 lines removed, single point of truth for tracker client setup.

### Step 4: DRY — Constants
**Problem:** DHT bootstrap nodes, ban thresholds, and block timeouts were hardcoded in 3 places with conflicting values.
**Fix:** Promoted all to `Utils.hpp` as `constexpr` / `inline constexpr` arrays.
**Tradeoff:** Merged DHT bootstrap nodes to the union of all lists (4 nodes instead of 2–3 per source) to avoid losing connectivity.

### Step 5: SoC — Tracker HTTP fetches
**Problem:** `main_client.cpp` contained raw HTTP GET logic for tracker list fetching.
**Fix:** Moved `fetch_tracker_list` / `http_get_trackers` into `TrackerClient.hpp` alongside other HTTP tracker utilities. Also promoted `trim()` to `Utils.hpp`.
**Result:** `main_client.cpp`: 530 → ~191 lines by the end of step 7.

### Step 6: DIP / SoC — Remove terminal I/O from storage
**Problem:** `FileManager::async_prompt` wrote to `std::cout` and read from `STDIN_FILENO` — the storage layer shouldn't know about terminals.
**Fix:** Stubbed the function to always auto-approve. (In a real app, injection via a callback or interface would be appropriate — YAGNI deferred that.)
**Why it's acceptable:** The prompt was only used for "file already exists, overwrite?" in a non-interactive CLI; auto-approve matches actual usage.

### Step 7: SRP / KISS — Extract TUI from client entrypoint
**Problem:** All terminal-interactive code (raw terminal, stdin loop, live display) lived in `main_client.cpp`.
**Fix:** Extracted `src/Tui.hpp` with `ClientTui`, `ScopedRawTerminal`, and `LiveDisplay`.
**Result:** `main_client.cpp` slimmed from 530 to 191 lines.

### Step 8: DIP / YAGNI — Wire all config knobs
**Problem:** `ClientConfig` had many unused fields (`enable_dht`, `enable_lsd`, `enable_pex`, `max_connections`, etc.) that were never read.
**Fix:** Wired every knob to its enforcement point — DHT/LSD/PEX gates, PeerManager limits, PieceManager timeouts, peer ban thresholds.
**Vindication:** The config system went from decoration to fully functional; YAGNI did not apply because the knobs were already defined with user intent.

### Step 9: SRP — Extract TrackerManager
**Problem:** `TorrentSession` (~1655 lines) owned tracker announce logic, backoff, tiered client management, and the announce callback chain.
**Fix:** Extracted `src/TrackerManager.hpp` / `.cpp` — ~160 lines + 7 member variables moved.
**Result:** `TorrentSession.cpp` shrunk from 1655 to 1495 lines.
**Design note:** `TrackerManager` communicates discovered peers via `PeerConnectCallback` (a `std::function`) rather than taking a direct `PeerManager` dependency, preserving SoC.

## 2. `bad_weak_ptr` During Construction

**Symptom:** When `TorrentSession` started a `TrackerManager` inside its constructor, `shared_from_this()` threw `bad_weak_ptr`.

**Root cause:** `shared_from_this()` requires the object to already be managed by a `shared_ptr`. During construction of a class created via `std::make_shared<TorrentSession>(...)` or equivalent, the `shared_ptr` control block exists but the `weak_ptr` internal to `enable_shared_from_this` isn't initialized until the constructor body finishes. Calling `shared_from_this()` inside the constructor body is undefined behavior / throws.

**Fix:** Deferred `TrackerManager` creation to a lazy `ensure_tracker_manager()` method called from `run()`, `add_tracker_url()`, and `set_tracker_announce_interval()`. The constructor only stores trivial config fields.

```cpp
// Before: constructor called ensure_tracker_manager() → bad_weak_ptr
TorrentSession::TorrentSession(...) {
    ensure_tracker_manager(); // BOOM
}

// After: constructor does nothing; ensure_tracker_manager() is lazy
void TorrentSession::ensure_tracker_manager() {
    if (!tracker_manager_) {
        tracker_manager_ = std::make_shared<TrackerManager>(...);
        // safe to use shared_from_this() here — called from run() etc.
        tracker_manager_->set_peer_callback([weak = weak_from_this()](auto peers) {
            if (auto self = weak.lock()) { ... }
        });
    }
}
```

**Lesson:** `shared_from_this()` in a constructor body is always UB. Defer any initialization that needs `shared_from_this()` to a post-construction init method (run, start, init, etc.).

## 3. Circular `shared_ptr` Death Spiral

**Symptom:** After fixing `bad_weak_ptr`, `TrackerManager` and `TorrentSession` formed a reference cycle that prevented destruction. The session's destructor never ran.

**Root cause:** The `TrackerManager` stored a `std::function` callback that captured a `shared_ptr` to `TorrentSession`. `TorrentSession` owned a `shared_ptr<TrackerManager>`. Cycle: `TorrentSession` → `TrackerManager` → callback → `TorrentSession`.

```cpp
tracker_manager_->set_peer_callback(
    [self = shared_from_this()](auto peers) { // self keeps session alive
        self->on_peers_discovered(peers);
    }
);
```

**Fix:** Two-part approach:

1. **Stored callbacks** capture `weak_from_this()` instead of `shared_from_this()`:
   ```cpp
   tracker_manager_->set_peer_callback(
       [weak = weak_from_this()](auto peers) {
           if (auto self = weak.lock()) {
               self->on_peers_discovered(peers);
           }
       }
   );
   ```

2. **In-flight coroutines** still capture `shared_ptr` — this is correct because we want the session to stay alive while a coroutine is running:
   ```cpp
   asio::co_spawn(strand_,
       [self = shared_from_this()]() -> asio::awaitable<void> {
           co_await self->some_operation();
       },
       asio::detached
   );
   ```

**Why it's safe:** The cycle is broken at the stored callback level. In-flight `co_spawn` captures keep the session alive only for the duration of the async operation. When the coroutine completes, the `shared_ptr` is released and the session can be destroyed.

## 4. `stack-use-after-return` in SessionHandle

**Symptom:** ASan with `detect_stack_use_after_return=1` caught a use-after-return error in `SessionHandle`, the RAII helper for integration tests.

**Root cause:** `SessionHandle::SessionHandle(io_context, session, timeout)` spawned a coroutine with a lambda that captured the `stop()` promise by reference. If the coroutine outlived the `SessionHandle` constructor frame (which it typically does, since the coroutine runs asynchronously), the reference was dangling:

```cpp
// Simplified version of the bug:
SessionHandle::SessionHandle(io_context& io, auto session, auto timeout) {
    std::promise<void> stop_promise;  // stack-local!

    asio::co_spawn(io, [&stop_promise, session]() -> asio::awaitable<void> {
        // ...
        stop_promise.set_value();  // use-after-return if this runs after constructor returns
        // ...
    }, asio::detached);

    // Constructor returns — stop_promise is now a dangling reference
}
```

**Fix:** Replaced all stack-local `std::promise` / `bool` captures in `SessionHandle` constructors with a heap-allocated `std::shared_ptr<bool> alive_` guard:

```cpp
SessionHandle::SessionHandle(io_context& io, auto session, auto timeout) {
    auto alive = std::make_shared<bool>(true);

    asio::co_spawn(io, [alive, session]() -> asio::awaitable<void> {
        if (!*alive) co_return;  // bail if destroyed
        // ...
    }, asio::detached);

    alive_ = std::move(alive);  // keep alive for the handle's lifetime
}

SessionHandle::~SessionHandle() {
    *alive_ = false;  // signal all in-flight coroutines to bail
}
```

**Alternative considered:** `std::jthread` with a stop token, but that introduces thread overhead for what should be a lightweight guard.

**Lesson:** Any async init pattern that captures references to constructor-stack locals is a landmine. Use heap-allocated guards or move-only types into the coroutine.

## 5. Integration Test Flakiness: The `io_context::restart()` Trap

**Symptom:** Integration tests (`IntegrationTest.*`, `DHTNetworkTest.*`) would fail randomly — port conflicts, "address already in use", or deadlocks — when run as a suite. Each test passed individually.

**Root cause:** `TearDown()` in both test fixtures called `io_context::stop()` followed by `io_context::restart()`:

```cpp
void TearDown() override {
    test_io.stop();
    for (auto& t : worker_threads) t.join();
    test_io.restart();  // ← THIS IS THE BUG
}
```

`io_context::stop()` does NOT drain the handler queue. It prevents new handlers from being dispatched and lets `run()` return. Any handlers that were queued but not yet dispatched remain in the queue. When `restart()` is called, **those stale handlers become live again** and fire during the next `TEST_F`'s setup phase.

The stale handlers included:
- `http_listener` coroutines holding the old HTTP acceptor (port still bound)
- `udp_listen_loop` coroutines holding the old UDP socket
- Various completion handlers from the previous test's sessions

When the next test tries to bind port 6880, the old acceptor is still alive → "Address already in use". Worse, a stale handler might access objects from the destroyed test fixture → use-after-free.

**Fix:** Remove `restart()` entirely. Each `TEST_F` gets a fresh fixture instance with a new `io_context`, so restart is both unnecessary and harmful.

```cpp
void TearDown() override {
    tracker_.reset();
    work_guard.reset();
    test_io.stop();
    for (auto& t : worker_threads) if (t.joinable()) t.join();
    // NO: test_io.restart();
}
```

### 5b. Endgame Flakiness

**Symptom:** `IntegrationTest.Endgame` (2 leechers + 1 seeder) flaked ~20% of the time — one leecher would finish early, calling `close_all()` and leaving the other stuck at ~80%.

**Root cause:** With 2 leechers, piece distribution is unpredictable. When the first leecher completed, it triggered session cleanup that could interfere with the second's in-flight requests. This is a valid race condition in the test, not the product code.

**Fix:** Simplified to 1 leecher + 1 seeder. Endgame behavior is still exercised (the single leecher requests pieces normally, then enters endgame for remaining blocks), but there's no cross-leecher interference.

**Lesson:** Over-parameterized integration tests are flaky by default. Start with the minimum viable topology and add complexity only when it tests a specific scenario.

## 6. Missing HTTP Listener Shutdown

**Symptom:** The `Tracker` class had `stop_udp_listener()` but no `stop_http_listener()`. The HTTP acceptor was created as a local variable inside the `http_listener` coroutine, making it unreachable for external shutdown.

**Fix:** Changed the architecture:

1. `http_listener()` now takes a `std::shared_ptr<tcp::acceptor>` instead of creating one locally.
2. `Tracker` stores `http_acceptor_` (shared_ptr) as a member, created in `listen_http()`.
3. `stop_http_listener()` closes the acceptor, causing the in-flight `async_accept` to complete with `operation_aborted`, cleanly terminating the coroutine.
4. Used the three-step open→set_option→bind→listen pattern so `SO_REUSEADDR` is set before binding (critical for rapid restart on the same port).

```cpp
void listen_http(int port) {
    stop_http_listener();  // close any old acceptor first
    http_acceptor_ = std::make_shared<tcp::acceptor>(io_context_);
    http_acceptor_->open(tcp::v4());
    http_acceptor_->set_option(tcp::acceptor::reuse_address(true));
    http_acceptor_->bind({tcp::v4(), (unsigned short)port});
    http_acceptor_->listen();
    asio::co_spawn(io_context_,
        http_listener(io_context_, http_acceptor_, router),
        asio::detached);
}

void stop_http_listener() {
    if (http_acceptor_ && http_acceptor_->is_open()) {
        boost::system::error_code ec;
        http_acceptor_->close(ec);
    }
}
```

## 7. Bonus: `TrackerDirectTest` Port Races

**Problem found during fix #6:** `TrackerDirectTest::PersistenceRoundTrip` calls `start_tracker()` twice in sequence in the same test. Without `stop_http_listener()`, the second call would create a new acceptor while the old one (still referenced by the in-flight `http_listener` coroutine) held the port → "Address already in use".

**Fix:** `listen_http()` calls `stop_http_listener()` at the start to close any existing acceptor before creating a new one. Coupled with `SO_REUSEADDR` set before bind, this makes rapid re-listen reliable.

## Key Takeaways for C++ Async Code

1. **Never call `shared_from_this()` in a constructor.** Defer to a post-construction init method.
2. **Break `shared_ptr` cycles:** stored callbacks use `weak_from_this()`, in-flight coroutines use `shared_ptr`.
3. **Stack-local captures in async init are UB.** Always heap-allocate guards or move data into the lambda.
4. **`io_context::restart()` re-activates stale handlers.** Don't use it between tests — each test fixture should create a fresh io_context.
5. **Set `SO_REUSEADDR` before `bind()`.** The three-step `open()` → `set_option()` → `bind()` → `listen()` pattern is the only way to ensure it takes effect.
6. **Minimal test topologies are less flaky.** Start with 1 peer when 1 peer suffices.
7. **Test after every refactoring step.** Prevents accumulation of subtle breakage.
