# Leak Hunt: 61 Indirect Leaks, Zero Direct — the Session Upload Limiter Trap

**Date:** 2026-08-02

## Session Overview

Four problems fixed in the Debug (ASan/LSan) build, ending with a clean full-suite gate:

1. **DHT teardown hardening** — self-bounding Kademlia queries (expiry timers, idempotent completion, drained `stop()`)
2. **ASan `stack-use-after-return`** — `SessionHandle::set_done` resumed on a FileManager pool thread after destruction
3. **Endgame pipeline underflow** — unsigned subtraction on duplicate blocks stalled a peer permanently
4. **LSan: 61 indirect leaks / 0 direct** — a session graph pinned by a suspended upload-rate-limiter coroutine at teardown

Below, each problem with root cause, fix, and reasoning.

---

## 1. DHT Teardown Hardening (Kademlia)

**Problem:** Stress runs (7592-lookup DHT tests) occasionally hung or leaked: queries could outlive `DHTNode::stop()`, keep-alive timers fired after teardown, and completion handlers could be invoked twice.

**Fix:**
- Queries are self-bounding: each `QueryState` gets an expiry timer; a completion is idempotent (first call wins, timer cancelled).
- A `cleanup_loop` sweeps expired entries so `pending_queries_` can't grow unboundedly.
- `DHTNode::stop()` moves `pending_queries_` out under `queries_mutex_`, then invokes completions **after releasing the lock** — avoids the reentrant deadlock that a previous design risked.
- DHT node itself is now lazily created (`dht_node_(nullptr)` + `make_shared` in `run()`) so sessions that never enable DHT skip the machinery entirely.

**Verified:** three consecutive clean stress runs (0 failures), then all temporary diagnostic guards were stripped.

---

## 2. ASan `stack-use-after-return` in `SessionHandle::set_done`

**Symptom:** `detect_stack_use_after_return=1` caught a use-after-return at `integration_test.cpp:182` (`SessionHandle::set_done()`), resumed on a **FileManager pool thread** — after the handle had been destroyed.

**Root cause:** The `on_piece_block` download-complete path flushed dirty blocks, and the flush's `operation_canceled` was swallowed by the completion lambda. After `stop()` began, the coroutine could still resume the download-complete path on a pool thread, touching a `SessionHandle` whose frame had already returned.

**Fix:** Shutdown guard in `TorrentSession::on_piece_block` after the flush:

```cpp
co_await flush_all_dirty();  // or equivalent
if (shutting_down_.load(std::memory_order_acquire)) co_return;
```

A `std::atomic<bool>` member is visible across threads; the guard makes teardown paths idempotent. No ASan errors in any subsequent run.

## 3. Endgame Pipeline Underflow

**Problem:** In endgame, duplicate blocks for the same piece are requested from multiple peers. The pipeline counter used unsigned arithmetic; a duplicate block's arrival underflowed the counter, leaving the pipeline permanently "full" — the peer stalled forever.

**Fix:** Clamp the pipeline counter at zero on decrement (saturating semantics) so duplicate/out-of-order arrivals can't wedge the accounting.

---

## 4. LSan: 61 Indirect Leaks, Zero Direct

**The main event.** The full suite passed all 211 tests but exited 1 with `LSan: 61 indirect leaks (21,574–21,742 B)`. Deterministic — it reproduced in `IntegrationTest.ChokingAlgorithm` standalone.

### Reading the LSan output

- **61 indirect / 0 direct** is LSan's trademark for a heap-only `shared_ptr` cycle: the heuristic classifies every block in a pure cycle as *indirect* because none is reachable from a root. Not a signal that the root is a global/static.
- Coroutine frames are heap blocks too. A suspended coroutine prints `.resume` at the top of its stack, with the **allocation site as `#1`** — that's how you find *where* the coroutine was created.

### Evidence chain

Destructor instrumentation (temporarily added, since stripped) showed exactly one session graph never destroyed: the **slow leecher** (session port 6883; `PEER_PORT_BASE=6881`, so seeder=6881 / fast=6882 / slow=6883).

Leak frames pinned the chain:

```
PeerConnection::message_loop()          (created in start_loops)
  → on_block_request
    → await_upload_tokens  [.resume]
      → AsyncRateLimiter::await_tokens  (suspended)
        → 4 queued Waiter nodes = std::pair<size_t, any_completion_handler<void(error_code)>>
```

**Root cause:** The slow leecher's **session-level upload limiter** (10 KB/s) could not satisfy a 16 KB block request: the 1 KB/100 ms refill needs ~1.6 s per block, and the token budget was exhausted at teardown. The waiter queued; then `TearDown` stopped the io_context before the refill timer fired — so the waiter was **never completed**. `message_loop` suspended forever → conn → `events_` (session) → whole graph pinned.

The session's limiters were value members (`TorrentSession.hpp:187-188`) and **`stop()` never stopped them** — nothing aborted the queued waiters.

### Fixes

1. **`TorrentSession::stop()`** now calls `upload_limiter_.stop(); download_limiter_.stop();` (after piece manager shutdown, before tracker cancellation). `AsyncRateLimiter::stop()` sets `shutting_down` and completes all queued waiters with `operation_aborted`, so any `message_loop` suspended in `await_tokens` unwinds cleanly and the session graph frees.

2. **Secondary hole:** a conn that dropped mid-test (removed from `active_connections_`, so `close()` never runs) pinned its session for up to 2 minutes via the keep-alive loop's `shared_from_this()`. Fix: `message_loop` calls `keep_alive_timer_.cancel()` on exit (after socket close / catch).

### Instrumentation insight

During the hunt, logging confirmed the slow leecher's `message_loop` was executing a REQUEST handler while its keep-alive got cancelled at teardown — the two fixes are complementary: the limiter stop unwinds the suspended handler; the keep-alive cancel prevents the alternate pinning path.

## Key Takeaways

1. **`LSan: N indirect / 0 direct` means a pure heap `shared_ptr` cycle** — treat it as "cycle reachable from nothing," not "no root." Instrument destructors to find which object graph survives.
2. **Suspended coroutine blocks print `.resume` at top with the allocation site as `#1`** — read `#1` to find where the coroutine was created.
3. **Rate limiter waiters are teardown traps:** any limiter whose refill timer lives on an io_context that can be stopped before pending waiters complete will pin whatever awaits it. `stop()` must complete queued waiters with `operation_aborted`.
4. **Stored callbacks capture `weak_ptr`, in-flight coroutines capture `shared_ptr`, and teardown must have a hard abort path** — otherwise the in-flight capture *is* the leak.
5. **`std::atomic<bool>` shutdown guards are the correct tool for cross-thread idempotent teardown** (ASan fix), and keep-alive timers need cancellation on every exit path (leak fix #2).
